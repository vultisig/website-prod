# Motion Direction: Vultisig Navbar Logo — Lighthouse Sweep

_Spec by /m-explore, 2026-06-11. Feeds /m-create._

## Mode
**2 — Illustrative / Standalone** (animated logo). Illustrative canon governs: expressive timing allowed, loop craft rules apply. Navbar placement caps amplitude — this is a quiet guardian, not a hero performance.

## Anchor
**Anchor:** Lighthouse sweep — slow gradient glint passes, calm, guardian-like.
**Anti-anchor:** Not a crypto-site neon pulse, not a spinning coin, not a shimmer-skeleton loading effect.

## Deliverable & Destination
Animated navbar logo mark (43×41px, `public/logo.svg` — 6 gradient blade paths: 2 left wing, 2 stem, 2 right wing, mint #33E6BF → blue #0439C7) → `components/navbar.tsx` in this repo. Web-only.
**m-create target:** CSS (or existing `motion` v12) code in-repo — the repo already uses motion v12; no new dependency.

## Selected Direction
1. **Placement:** `Navbar mark` — small, seen on every page; quiet life only.
2. **Personality:** `Premium` — 350–600ms range for any non-beam moves, `cubic-bezier(0.4, 0, 0.2, 1)`, 0% overshoot. No bounce anywhere.
3. **Trigger model:** `Hover-summoned` — static at rest. Sweep plays once per hover. PLUS one greeting sweep ~600ms after first paint per page load. A started sweep always completes, even if the pointer leaves.
4. **Amplitude:** `Light only` — geometry fully frozen (no scale, no rotation, no translation). A soft-edged brightness band travels across the mark through the gradient.
5. **Sweep easing:** `True beam` — linear travel, soft-edged band (canon constant-motion exemption: lighthouse beams don't ease). Band edge softness carries the elegance, not the easing.
6. **Sweep duration:** `1100ms` for one full pass (both load-in and hover).
7. **Signature moment:** `Stem holds the light` — beam crosses wings left→right; the two central stem blades catch the brightness and HOLD it ~150ms longer before releasing (Premium-eased decay, `(0.4, 0, 0.2, 1)`). The vault spine keeps the light.
8. **Blade sequencing:** light strikes blades in geometric order as the band passes — left-wing pair → stem pair (hold) → right-wing pair. Stagger emerges from band position, not artificial delays.
9. **Loop/seam rule:** sweep is one-shot per trigger; rest state before == rest state after (first frame == last frame). No idle/ambient motion at rest.
10. **Anti-reference:** the generic CSS `shimmer` skeleton effect; Stripe-style continuous gradient rotation.

## Constraints
- **prefers-reduced-motion:** no sweep at all. Hover = instant ~8% brightness lift, 150ms ease-out fade on leave. Designed cut, not a deletion.
- **Stack:** repo already ships `motion` v12 + Tailwind; prefer pure CSS (mask/gradient overlay + `@keyframes`) — zero JS for a decorative effect; `motion` only if the stem-hold needs orchestration CSS can't express cleanly.
- **Performance:** transform/opacity/mask only — no filter:blur() animation at 60fps on a nav element; band as a masked overlay gradient, GPU-composited.
- **Accessibility:** logo remains a plain link; animation decorative (`aria-hidden` on the effect layer); no interaction blocked at any point.
- **Implementation note:** sweep must work against `public/logo.svg`'s existing per-blade linearGradients — likely approach: inline the SVG in navbar (it may already be `<Image>`; m-create to check) and overlay a moving highlight via CSS mask compositing per blade group.
